# Principles

1. Methodology is versioned as code beside contracts, workflows, profiles, policies, and skills.
2. Claims follow evidence. A check is `passed` only after an observed zero exit code or another explicitly linked artifact.
3. Development is project-native: discovery records the architecture before implementation begins.
4. Core workflow intentions are platform-independent; adapters own toolchain commands.
5. Rigor is selected by profile and risk.
6. Uncertainty is recorded as `blocking`, `assumption`, `deferred`, or `resolved`.
7. Changes remain local, scoped, and reversible.
8. Humans retain authority over dependency, public API, migration, privacy, destructive, publish, and release decisions.

The MVP adopts Superpowers as the normative method for R&D and verification, and MobileBuildMCP as the Apple execution backend. Local skills specialize those methods for mobile work; they do not replace them.
